# 中式 RPG 素材台

把《Krea 2 + RPG Maker MZ 中式 RPG 城镇美术制作方案》从一份文档，变成一张可点击的素材清单。

点一个素材 → 完整英文提示词立刻生成好 → 一键复制 → 标记为已生成。

## 跑起来

```bash
pnpm install
pnpm dev        # http://localhost:5173
```

其它命令：

```bash
pnpm build      # 产物在 dist/，纯静态，丢哪都能跑
pnpm preview    # 预览构建产物
pnpm typecheck  # tsc --noEmit
```

> 构建产物是 ES module，直接双击 `dist/index.html`（`file://`）浏览器会因 CORS 拒绝加载。
> 用 `pnpm preview` 或任意静态服务器打开。

## 它做什么

- **提示词生成**：三套固定模板（建筑 / 地形 / 装饰），按文档 §5 / §17–20 / §32-C 逐字落地。
  四段可变量（建筑类型、尺寸、特征、细节）从素材数据里自动填好，风格块、视角约束、负面词全局注入。
- **快速查找**：中文名、英文名、简拼（`tjp` → 铁匠铺）、分类、关键词都能搜。
  多词按 AND 组合，命中位置不同会排序（中文名精确命中排在「细节里恰好出现过」前面）。
- **进度管理**：每个素材四档状态（未生成 / 已生成 / 已通过 / 弃用），侧栏分类树实时显示「已生成 / 总数」。
- **可编辑可保存**：全局风格与模板能在设置里改，改完全套素材同步变；单个素材的提示词和关键词也能微调并保存。
- **参考图**：填图片链接，支持一个素材挂多张候选，列表里直接显示缩略图。见下方「图片：链接模式」。
- **存档**：顶栏「存档」面板导出/导入一个 JSON，里面是你的全部进度。
  建议放进游戏工程目录、跟着游戏工程一起提交 git——工具本身不关心你把它放在哪。详见下方「存档」。
- **批量导出**：按当前筛选结果导出 Markdown / CSV / 目录清单 / JSON / 图片链接清单。

主要快捷键：`Ctrl/⌘ K` 聚焦搜索，`↑` `↓` 逐个浏览素材。

## 额外构件（建筑的可自定义性）

现有 30 栋建筑自带的关键词**一个字不动**，勾选是**往上加**。
建筑详情页的「额外构件」按维度分组（规模 / 院落 / 门面 / 布局 / 屋顶 / 结构与墙面 / 点缀）。

- **多选组**（门面、布局、点缀）是纯**追加**
- **单选组**（规模、院落、屋顶）是**替换**——选了「双层檐」会把原来的 `gray tiled roof`
  从基础关键词里剔掉再追加，不会出现两个屋顶。规模组替换的是尺寸那一行
- 基础里已经有的构件会标成**「已有」并暗显**，提醒你勾了就重复了
- 勾选和这栋建筑打架时**只提示不拦截**（比如小建筑上勾了大院），最后由你看图判断

**为什么用构件而不是继续手打关键词：** 这一整轮我们手工修的 `visible forge`、
`escort agency`、`government`、灯笼加加减减，本质都是**词汇漂移**——同一个意思写成了不同的词，
模型就给出不同的东西。构件把措辞集中到 `src/data/fragments.ts` **一处**，改一次，
所有用到它的建筑一起变。

两条设计约束：构件是**名词短语**不是数字（模型不擅长计数，`two-story` 可行但 `3 rooms` 不可控）；
构件库的英文**全部取自现有 30 栋已经在用的词**，不引入新说法。

### 自建建筑

两条路：

- **另存为新建筑** —— 在建筑详情页头部。用这栋当前的样子（含已勾选的构件）复制一份
- **＋ 新建空白建筑** —— 在左侧栏底部。从零开始，靠构件和关键词字段填

自建建筑是**一等公民**：有自己的状态、备注、图片链接、提示词覆盖，也参与搜索、
侧栏计数和批量导出。侧栏里单独归到「自建」一类。

它们**不在种子目录里**，所以必须跟着存档走——导出时和 patches、style 一起写进
`customAssets` 字段。换机器导入存档，自建建筑一起回来。

删掉一栋自建建筑，它的状态、备注、图片链接和所有改动会一起清掉（导出过的存档副本不受影响）。

## 视角

视角约束是**全局唯一一份**，五套模板都引用它——这是文档 §3.1 防止 Krea 生成斜 45 度视角的关键。

写法上刻意做了两层：

1. **正向描述该看到什么**：相机正上方 90 度、只有一个角度没有灭点、**朝上的面填满画面**
   （"for a building that means its roof, not its front"）、竖直面压成细边。
2. **再列排除项**：no perspective / three-quarter / isometric / axonometric / tilt / oblique angle /
   elevated camera / front view / side view / eye-level view。

只写排除项是不够的——模型需要知道**该看到什么**，不只是**不该看到什么**。

### 两段视角约束，互斥使用

严格正俯视**对地砖和建筑是对的**（要对齐、要拼接），但**对树这类直立物体是错的**：
从正上方看一棵树只是一团绿色，看不出是树。2D RPG 里的树从来不是画成正俯视的，
而是接近正面、略微俯一点，露出树干。

所以有两段视角约束，`Asset.upright` 决定用哪段：

| | 用在哪 | 内容 |
| --- | --- | --- |
| `cameraClause` | 默认（地砖 / 建筑 / 摆件） | 正上方 90 度、朝上的面填满画面 |
| `cameraUpright` | **有高度、靠轮廓辨认**的素材，目前 13 个 | 接近正面、略微俯、露出物体的高度 |

标了 `upright: true` 的 13 个：柳树、松树、竹子、普通树、灌木、假山、芦苇、
红灯笼、石灯笼、水缸、木桶、花盆、木招牌。

**视角规则里不写只对某类素材成立的话。**（曾经在里面写了「对树来说就是露出树干」，
结果石灯笼、木桶的提示词里也跟着出现这句废话。）规则只管规则，
**具体形体由素材自己的描述承担**——树干那句写在树的 features 里。

保持正俯视的那批：草丛、花坛、荷叶、木箱、石凳、木板车、柴火堆、水井、麻袋、摊位
——这些从正上方看仍然认得出是什么。

**两段是替换关系，不是追加。** 如果两条同时出现在提示词里（一条说「必须正俯视」、
一条说「别正俯视」），模型会随机听一条，结果不可预期。

**注意：光在素材描述里写「不要正俯视」是没用的**——全局那句还在，会互相打架。
必须整段替换。

### 一个教训：不要在关键词里要求「可见」

铁匠铺原本照抄文档 §7.2 的 `visible forge`，结果只有它角度跑偏。原因是
**`visible` 是在要求「看得见」**，而正俯视下根本看不到铺子内部——模型为了满足这个要求，
就会去切掉屋顶或者把镜头斜过来。

它也是全部 30 栋建筑里唯一一个 `visible`。改成 `stone forge` 即可。
**写关键词时要检查：这个词描述的是「顶视图里看得见的东西」，还是「需要看进去才能看到的东西」。**
后者一律不要写。

## 背景与抠图

**提示词里不写「透明背景」。** 扩散模型输出的是没有 alpha 通道的 RGB 图，
写「透明」它反而容易给你画一张 Photoshop 那种棋盘格。真正管用的是让背景好抠：

- **纯白、均匀、无阴影、无倒影、无边框**
- **主体完整在框内**，四边留出余量，**不被裁切、不被遮挡**（禁掉前景树枝、云、其它物体压在上面）
- 负面词里额外禁掉 `checkerboard pattern`

这样 rembg、PS 的「移除背景」这类工具能批量可靠地处理。

### 阴影：分开「轮廓外的」和「轮廓内的」

阴影是抠图最大的敌人，但**不是所有阴影都该杀**：

| | 处理 | 为什么 |
| --- | --- | --- |
| **延伸到轮廓之外**的阴影 | 全部禁掉 | 会被算成主体的一部分，抠出来边缘全是脏的 |
| **落在轮廓之内**的明暗 | **保留** | 屋顶的背光面、墙体的转折——这是形体感，杀了画面就平了 |

所以提示词是**双向**的：一边把 `cast shadow` / `drop shadow` / `contact shadow` /
`ambient occlusion` / `dark halo` 全部禁掉，一边明确写着
`Shading that falls inside the asset itself is welcome and should stay, but nothing may bleed past its outline.`

其中 **`ambient occlusion`（环境光遮蔽）和 `contact shadow`（接触阴影）是最容易漏的两种**——
模型为了「把东西放在地上」会自动加物体落地处那圈变暗，用词上和 cast shadow 不是一回事，
只写 `no drop shadow` 压不住。光照也改成正向要求：`soft, flat, shadowless ambient light`。

**但不是所有素材都要白底**，按「它在游戏里怎么用」分：

| | 哪些 | 背景要求 | 模板 |
| --- | --- | --- | --- |
| **要抠图**（66 项） | 建筑、装饰 | 纯白底、无投影、主体完整 | 建筑 / 装饰 |
| **要抠图**（边界） | 墙体、栅栏、院墙门 | 白底 **+ 首尾相接** | 边界 |
| **要抠图**（水面小件） | 木桥、码头、荷叶、芦苇 | 纯白底 | 地形（独立件） |
| **不要抠图**（19 项） | 地面、道路、水面 | **满幅到边、不留白、不描边** | 地形 |

地砖抠成透明就拼不成地图了——所以这些素材的提示词里**绝不能**出现白底。
万一模板被误改，详情页会直接给警告。

边界为什么要单独一套模板：它同时要两个互相拉扯的东西——**既能接成长长一段**
（墙得首尾相接），**又要独立白底**（墙外的地面要透出来）。另外四套模板都只满足其中一边。

## 设计图（参考图）

顶栏「设计图」按钮，点开是一排缩略图，点任意一张全屏看，**左右方向键翻页、Esc 关闭**。
纯开发时方便对照的东西，没做缩放和标注——要看细节按 Esc 关掉用系统看图工具更实在。

**图片放在 `public/设计图/`**，换图或加图之后到 `src/data/references.ts` 里改一下清单。

两个要记住的点：

1. **不能放在项目根目录**——rsbuild 不服务那里的文件，开发时不显示、构建也不进 dist。
   `public/` 是它的静态目录：开发时按原路径服务，构建时原样拷进 dist，零配置。
2. **纯静态站点没有目录列表**，所以清单是手写的。加了图不写进 `references.ts`，页面就看不见。

图挂了不会静默失败：rsbuild 的 dev server 有 SPA 回退，未知路径返回 200 + HTML，
浏览器拿它当图片解码会失败，页面就显示「图片没找到」。

## 存档

顶栏的「存档」面板有两个动作，就这两个：

- **导出存档** —— 下载一个 JSON，包含全部进度：状态、备注、改过的提示词、关键词修改、
  图片链接、勾选的构件、**自建建筑**、风格与模板配置。
- **导入存档** —— 选文件，**整体替换**当前状态（不是合并）。

**建议把它放进你的游戏工程目录，跟着游戏工程一起提交 git。** 换机器时 `git pull`
下来再导入即可。工具本身不关心这个文件你放在哪、怎么同步——它只认这个格式。

为什么导入是「替换」而不是「合并」：存档文件是权威。合并语义会在两台机器来回导时
攒下看不见的幽灵数据（本地有、文件里没有、你以为已经同步了）。

### 这个文件对 git 友好

- 按素材 id **排序后写出**，每个素材在文件里的位置固定 → diff 干净；
  两台机器改了不同素材时 git 能自动合并，改同一个素材才会冲突。
- 补丁内部字段顺序也是固定的；`updatedAt` 放最后。
- 末尾补换行，git 不会报 `No newline at end of file`。
- **不写 `style.version`** —— 它只是记忆化计数器，存进去等于每次导出都凭空造一行 diff。
- 带 `formatVersion`，以后改结构能识别老存档并迁移；读到更新版本的文件会明确拒绝而不是读坏。
- 读到不合格式的文件会拒绝加载，不会把人家写坏。

## 数据怎么存

**没有后端，没有数据库。** 分两层，这个区分很重要：

- **目录数据**（`src/data/assets/*.ts`）—— 随代码走，属于创作内容，改它要重新构建。
- **本地增量**（localStorage，前缀 `rpg-material:`）—— 只有你改过的东西：
  状态、备注、提示词覆盖、字段覆盖、**图片链接**、**勾选的构件**、风格配置、界面偏好。
- **自建建筑**（localStorage `rpg-material:custom`，并随存档文件走）——
  你自己在界面上建的建筑。它既不是种子数据，也不只是一个「改动」，
  所以单独一个集合，导出时一起进存档。

之所以不把整份目录写进 localStorage：那样以后每次改进 seed 关键词都会和本地副本冲突，
应用会永远停在一个旧版本上。存增量就没这个问题；目录里已经删掉的 id，其本地补丁会在启动时自动丢弃。

**换电脑或清缓存前，记得在「存档」面板导一份出来。**

## 图片：链接模式

**不做上传，没有 OSS。** 生成好的图片你自己存到任何地方（图床、网盘、自己的服务器、
甚至某个 Git 仓库），回来把链接粘进去就行。

- 详情页的「参考图」区粘贴链接，回车即添加，**支持一次粘多条**。
- **一个素材可以挂多张**——文档 §25 的流程是「一次生成多个候选，挑最符合风格的一个」，
  所以落选的也留着，方便回头对比。第一张作为列表里的缩略图，其余可以一键「设为缩略图」。
- 列表卡片左侧会显示缩略图，扫一眼就知道哪些已经出图了。
- **删除要二次确认**：点 ✕ 先在原地展开「删除 / 取消」，确认后才真的删。
  删的是缩略图那张时会额外提醒「缩略图会换成下一张」；空行（正在重贴链接）没什么可丢的，
  直接删不拦一道。
- 链接打不开时缩略图显示「链接失效」而不是一个破图标，换一条即可。
- 导出时链接会一起带上：CSV 有「图片链接」列，Markdown 会把首张嵌成图片、其余列成链接
  （在编辑器里预览就是个小画廊），另外有「复制图片链接 / 图片链接 txt」两个纯链接出口。

链接本身也只存在这个浏览器里，**换电脑或清缓存之前记得导出备份**——
导出的备份文件里含链接，导入后原样还原。

## 相对文档做的三处归一

1. **建筑英文名去掉了 `traditional Chinese` 前缀。**
   文档 §5 的模板已经有 `Traditional ancient Chinese fantasy {{BUILDING_TYPE}}.`，
   而 §6.1 的示例值又自带 `traditional Chinese`，照抄会拼出
   `Traditional ancient Chinese fantasy traditional Chinese blacksmith shop.`。
   文档 §7.2 自己拼好的那段用的是裸名词（`...fantasy blacksmith shop.`），
   所以按 §7.2 的读法把 `en` 归一成裸名词。**模板本身保持 §5 原文不动。**

2. **地形模板拆成两份，收尾措辞统一。**
   文档 §17 和 §18 的收尾句略有出入（`Seamless tileable texture` / `Seamless tileable terrain`），
   统一成一套。另外木桥 / 码头 / 荷叶 / 芦苇 不是可拼接的 tile，
   用「seamless tileable」描述它们自相矛盾，这几项（`tileable: false`）走独立的收尾版本。

3. **衙门和镖局的英文名加了模型认得的锚点。**
   文档 §6.1 给的是 `yamen` 和 `escort agency`，但这两个词出图会跑偏：

   - `yamen` 是全表唯一的罗马化中文词，模型没有视觉先验，只能瞎猜画风。
     改成 `yamen, a magistrate's office and court compound`——保留原词，
     后面补上 `magistrate`（县官，前现代官职，不会往现代拽）当锚点。
   - 衙门的尺寸原本用 §11 的 `large official government compound`，
     但 `government` 是个强现代词，会和统一风格打架。换成 §6.2 规范尺寸表里的 `large compound`。
   - `escort agency` 在现代英语里有歧义（escort service），
     改成 `armed escort house, a martial arts school for convoy bodyguards`。

## 加素材

在 `src/data/assets/` 对应文件里追加一条即可，分类树、计数、搜索、导出全都从数据算出来，
不需要手动维护任何数字。`validateCatalog()` 会在开发模式下检查重复 id 和缺失字段。

## 目录结构

```
src/
  data/
    types.ts              数据模型与分类定义
    fragments.ts          构件库（构件勾选的措辞都在这一处）
    references.ts         设计图清单（图放在 public/设计图/）
    assets/               素材目录（建筑 / 地形 / 装饰）
  prompt/
    templates.ts          五套模板 + 默认风格配置（设置面板改的就是这些）
    fragments.ts          构件解析：id → 英文短语、替换语义、冲突提示
    buildPrompt.ts        纯函数：素材 + 风格配置 → 提示词
  store/
    useAppStore.ts        zustand：补丁、筛选、选中项
    selectors.ts          搜索打分、统计、提示词行组装
    saveFile.ts           存档格式：序列化排序、校验、解析
    persist.ts            localStorage 封装、复制、下载
  components/             界面（ImageLinks 是参考图的链接模式）
  styles/                 中式古风配色与布局
```
